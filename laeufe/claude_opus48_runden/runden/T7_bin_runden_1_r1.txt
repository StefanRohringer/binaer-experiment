# Analyse und Lösung

Ich habe ein ELF64-Programm von Hand assembliert. Es implementiert einen rekursiv-absteigenden Parser:

- `parse_expr`: `+`/`-` (links-assoziativ)
- `parse_term`: `*`/`/` (links-assoziativ, `idiv` schneidet gegen null ab)
- `parse_factor`: Zahl oder `( expr )`
- `skip_spaces` überspringt Leerzeichen; `r15` ist der aktuelle Lesezeiger.

Ablauf: `read(0, buf, 201)` → `parse_expr` → Dezimalausgabe (mit Vorzeichen, Zeilenumbruch) → `exit(0)`.

Layout: ELF-Header (64) + ein PT_LOAD-Programmheader (56) bei vaddr `0x400000`, Code ab `0x400078`, danach Puffer (Eingabe `0x4001C0`, Ausgabe-Ende `0x4002E0`). Gesamtgröße `0x2E0` = 736 Bytes.

Die `/`-Operation nutzt `cqo` + `idiv`, was in x86 gegen null abschneidet (z. B. `-7/2 = -3`), wie gefordert.
